# 09: 拍板：模型怎么写一次光顾

Type: grilling
Status: open
Blocked by: 06, 07

## Question

服务器定好角色、饮品、事件和判定，模型只负责把戏写出来。要定：

- **调用的切分**：一次光顾分几次调用（开场加点单、每杯的反应、告别），每次带什么：她的人设、IF 的设定和护栏、这次抽到的事件、服务器定好的点单和判定、前面已经说过的台词。要不要提示词缓存（`prompt-caching` 那套）。
- **输出格式**：一段里有她的日语台词加中文字幕、制作人的中文台词、偶尔的选项、每句的情绪（七种之一）。情绪是让写台词的模型一起标，还是像通话那样交给判断模型；立绘照情绪动。
- **状态存在哪**：光顾进行到哪一步、抽到的东西、已经说过的台词存在服务器（存库还是内存），刷新页面能不能接着玩；光顾的记录要保留多久，用来给「最近来过就避开同样的理由」用。
- **出错**：模型超时或者输出不合格式时怎么办（重试、用写死的兜底台词、这次光顾作废但不算当天第一次）。
- **自带 LLM**：用用户自己的模型时照常写；思考强度跟文字回合那一项走还是另设。
- **限额的数**：每小时光顾次数默认几次。

## Comments

### 票 05 交接

- 点单那一段由服务器给模型一张点单卡：说法、目标饮品的名字、口味、种类、描述、要提哪些条件、能不能说出名字。
- 写完后服务器检查名字：不该说名字的说法里，日语台词和中文字幕都不能出现任何饮品的英文名或日文名；该说名字的要说出来。不过就重写一次，再不过换成写死的模板句。这条要并进这里的「出错」规则。
- 她的日语台词用日文版译名（在 drinks.csv 的 name_jp），中文字幕用英文原名。

### 票 06 交接

- 骨架是 进门 → (点单 → 上酒反应 → 闲聊) × N → 告别，每段写什么、几句见票 06 的答案。哪几段并成一次调用在这里定。
- 光顾开始时服务器抽好、要和这次光顾存在一起的东西：角色、来意、话题、点几杯（1/2/3 杯，各 20/60/20%）。每单的目标饮品和说法在点单时再抽，还是开始时一起抽，在这里定。
- 每次调用要带的输入：IF 设定和护栏；她的人设和世界设定；好感度档位（关着时按正常值）；`today_lines`；如果来意来自日程，带那项工作的 name 和 note；她和这位用户在酒吧的记录（来过几次、上次多久以前、上次每单点了什么和上对没有、上次醉没醉）；点单卡；已经说过的台词。
- 酒吧要按用户、按角色存一份光顾记录。去重要用到最近 3 次的来意和话题，「老样子」要用到上次每一单点了什么。保留多久在这里定，至少要留够这些用途。
- 「请慢用」那句不交模型写，由服务器从写死的几句里挑。
